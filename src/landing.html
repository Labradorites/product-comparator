The problem

Buying an SSD means a week of tabs, spec sheets and reviews that disagree.

You compare models across Amazon, Shopee, Lazada and smaller shops, ask friends, and read reviewers you've never heard of. Pick the wrong form factor or interface and the drive won't fit at all. SSD picker is built to cut that week down to under an hour.

How a search runs

A language model reads and explains. Code decides what's real and what fits.

The model is good at reading plain English and writing a clear explanation. It is not trusted with prices or compatibility, so those steps are ordinary code you can read and test.

  1. You

    Describe the drive in one box

    Capacity, type and a budget if you have one. Internal M.2, internal 2.5" SATA, or external.

    "1TB M.2 NVMe under $120"

  2. Model

    Turns your words into filters

    type internal_m2 · form factor M.2 2280 · interface NVMe · 1000 GB · budget S$120

  3. Search

    Searches the web live

    Three neutral queries go out on every request, so any Singapore retailer can turn up, not only the big marketplaces. There is no stored catalogue to go stale.

  4. Model

    Pulls candidate offers from the results

    Product name, price, capacity and link for each offer it finds. At this point these are only claims.

  5. Code

    Checks every candidate against its page

    The link must be one the search actually returned. That page must show the exact price next to a currency marker, the capacity, and evidence of the drive type. The shop name comes from the link, never from the model. Anything that fails is dropped.

  6. Code

    Keeps only drives that fit, then ranks them

    Type, form factor and interface must equal what you chose. Survivors are sorted into within budget, over budget by a stated amount, and fits but misses a spec, each with a match score.

  7. Model

    Explains the picks

    The product rows on screen come straight from step 6. The model writes the explanation around them but can't add a product.

Dashed tag: language model. Solid purple tag: plain code with tests.

The check

Six offers go in. Three make it to your screen.

This is what steps 5 and 6 do to a typical batch of candidates. A made-up link, a price the page doesn't show, or a drive of the wrong type never reaches you.

What you can rely on

What it does today, and what isn't built yet.

Built

  • Compatibility is checked in codeType, form factor and interface must equal your choice. A drive that doesn't fit is never recommended.
  • Every price has a sourceEach offer shows the seller's link and the time it was retrieved, so you can confirm it before you buy.
  • Nothing in budget? You still see your optionsDrives that fit but cost more, with the exact amount over, and cheaper drives with the spec they miss.
  • No checkoutIt points you to the seller. You buy there.

Not yet

  • Price historyWhether to wait for a sale. This needs prices recorded over time, which hasn't started.
  • Seller trust scoresTrustpilot ratings for each shop are planned, so you can judge sellers you haven't used.
  • Demand testWill people use a recommendation instead of their own research? The test is designed with an 80% pass mark and hasn't been run.
